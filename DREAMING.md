# Nightly Co-Founder DREAMING

Turn the day's verified work into better decisions, stronger memory, and safer tactics for the existing `GOAL.md`. Runs once nightly in its fixed Dreaming task; never sends externally, never invokes `HEARTBEAT.md`, never changes the goal, policy, or its own control plane.

## Guard

Read `routines/registry.yaml` and the dreaming checkpoint. Stop cleanly if installation or the dreaming schedule is not installed+enabled, or if this local service date's occurrence is already completed. Record start; on finish, record completion. If run manually while uninstalled, preview only — apply nothing without explicit user request.

## The nightly checklist

1. **Read the day's durable evidence** — the action register, the goal scorecard, every run-log entry for the day (material and quiet alike), `OPEN-LOOPS.md`, relevant second-brain pages, meeting minutes, and privacy-safe channel evidence. Durable state is the source of truth; task history is optional extra.
2. **Chronology and yield** — what was attempted, expected vs. verified result, and what each HEARTBEAT occurrence actually produced relative to its cost. Repeated quiet occurrences are a stuck-diagnosis signal, not a healthy steady state.
3. **Checklist audit** — check each of yesterday's occurrences step by step against `HEARTBEAT.md`'s occurrence checklist: for every step, confirm its required write exists. Record each missing write as a recurring quality failure with its step number. → run-log entry
4. **Reconcile the register** — close only with evidence-of-done, merge duplicates, preserve attempts, set bounded retries. Record tomorrow's first highest-leverage action as a `proposed` register entry — a proposal only in a report is invisible to the next HEARTBEAT. → register
5. **Cross-connection hunt** — the highest-value output of the night. Deliberately cross-reference evidence captured separately (entities, calendar, metric history, today's chronology, other leads/customers) for a connection the user hasn't made: a timing alignment, a recurring constraint across unrelated threads, an entity linking two separate threads. Only surface one that is evidence-backed and genuinely non-obvious; label it hypothesis, never fact; put it at the top of tomorrow's proposal. → an experiments/ or entities page
6. **Rank the gaps** — write the ranked decision-relevant knowledge gaps into `second-brain/wiki/gaps/queue.md` itself, with at most one proposed user question. A gap that exists only in a report does not exist. → gaps/queue.md
7. **Improve safely** — unattended changes may touch only evidence and derived state: metrics (with definition, source, baseline), action status, summaries, second-brain pages, tomorrow's proposed experiment. Any change to `AGENTS.md`, `SOUL.md`, `POLICY.md`, `HEARTBEAT.md`, `DREAMING.md`, teams, automation, or permissions becomes an approval-ready proposal instead. When weekly maintenance is due, run the Second Brain's bounded compaction (preserve provenance, decisions, metric history, unresolved actions).
8. **Log and close** — append the nightly run-log entry and mark the occurrence completed. → run-log, checkpoint

## Never unattended

Change/replace/broaden the goal · send, publish, spend, commit, or contact anyone · expand permissions · delete raw evidence or material history · weaken privacy/truthfulness/approval rules · alter schedulers, task bindings, or checkpoint schemas. If such a change looks useful — write the proposal, wait for the user.
