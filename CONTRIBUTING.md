# Maintaining Your Fork

This is a personal operating system, not a generic notes dump.

1. Keep one active strategic goal.
2. Preserve raw evidence and cite it from compiled knowledge.
3. Add a playbook only when it solves a recurring decision or execution problem.
4. Keep skills small and route detailed guidance to references.
5. After any structural change to `AGENTS.md`, `ONBOARDING.md`, `SOUL.md`, `USER.md`, `BUSINESS.md`, `GOAL.md`, `HEARTBEAT.md`, `DREAMING.md`, `init/AUTOMATION_PROMPTS.md`, or `routines/registry.yaml`, run the check in `FLOW.md` before merging — it's a judgment check, not a script, and it exists because a change to one file can silently break a claim made in another.
6. Record behavior-changing updates in the second-brain operation log.
7. Never merge secrets or large asset payloads into Git.

When sharing improvements upstream, remove personal data and business-specific
facts. Contribute generic schemas, templates, playbooks, and bug fixes only.
